# Wiki 页面格式规范（schema.md）

本文件定义 llm-wiki 所有产出物的格式。LLM 在创建或更新任何 wiki 页面时，必须严格遵循这些模板。

---

## 一、概念页模板

**文件路径**：`知识库/概念/<id>.md`
**文件名规则**：中文概念直接用中文词，如 `注意力机制.md`；英文专有名词保留英文原名，如 `transformer.md`；混合概念以中文为主，如 `大语言模型.md`

```markdown
# <概念标题>

**标签**：`标签1` `标签2` `标签3`
**最后更新**：YYYY-MM-DD
**有冲突**：否

---

## 📖 知识摘要

<!-- consolidate 时重写此区。ingest 时不要改动此区。 -->

[综合整理后的知识，段落形式，包含来源引用]

来源：[来源文件名1]、[来源文件名2]

<!-- 如存在认知分歧，紧接摘要末尾放置分歧块 -->

---

## 📥 待合并内容

<!-- ingest 时追加到此区。consolidate 时清空此区内容（保留标题行）。 -->
<!-- 格式：每条独立 blockquote，带来源和日期 -->

```

### 📥 待合并内容区条目格式

每次 ingest 追加一条，格式严格如下：

```markdown
> **来源**：原文件名.md（YYYY-MM-DD）
>
> [从该文件提取的关于本概念的 3-5 条要点，段落形式]
```

### ⚡ 认知分歧标注块格式

当新资料与现有知识摘要存在矛盾时，在摘要末尾追加：

```markdown
> ⚡ **认知分歧**
> 外部资料认为：[外部观点的简洁陈述]
> 来源：[文件名]
```

**规则**：
- 不可静默合并分歧，必须用此格式显式标注
- 一个页面可有多个分歧块（按时间顺序追加）
- consolidate 后，分歧块保留在 📖 知识摘要区末尾，不删除
- 卡片接口开放后扩展为「外部资料认为 vs 个人笔记认为」双方对比

## 三、索引文件格式

### 3.1 概念索引.jsonl

**路径**：`知识库/索引/概念索引.jsonl`
**格式**：每行一条 JSON，不加逗号，不加数组括号

#### 条目字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 文件名（不含 .md）。中文概念直接用中文词，如 `注意力机制`；英文专有名词保留英文小写，如 `transformer` |
| `标题` | string | 概念的显示名称，**优先使用中文**；英文专有名词可保留原名，如 `Transformer`、`RAG` |
| `文件` | string | 相对于知识库根目录的路径，如 `概念/transformer.md` |
| `标签` | array | 字符串数组，用于分类和检索 |
| `有冲突` | bool | 是否存在未解决的 ⚡ 认知分歧 |
| `更新时间` | string | ISO 日期格式 `YYYY-MM-DD` |

#### 示例

```jsonl
{"id": "transformer", "标题": "Transformer 架构", "文件": "概念/transformer.md", "标签": ["深度学习", "注意力机制", "序列模型"], "有冲突": false, "更新时间": "2026-04-15"}
{"id": "检索增强生成", "标题": "检索增强生成（RAG）", "文件": "概念/检索增强生成.md", "标签": ["大语言模型", "信息检索"], "有冲突": true, "更新时间": "2026-04-16"}
{"id": "注意力机制", "标题": "注意力机制", "文件": "概念/注意力机制.md", "标签": ["深度学习", "Transformer"], "有冲突": false, "更新时间": "2026-04-14"}
```

### 3.2 实体索引.jsonl

**路径**：`知识库/索引/实体索引.jsonl`
**格式**：同上，每行一条 JSON

#### 条目字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 文件名（不含 .md） |
| `标题` | string | 实体显示名称 |
| `类型` | string | `人物` / `书籍` / `论文` / `工具` / `组织` |
| `文件` | string | 相对于知识库根目录的路径，如 `实体/andrej-karpathy.md` |
| `标签` | array | 字符串数组 |
| `更新时间` | string | ISO 日期格式 `YYYY-MM-DD` |

#### 示例

```jsonl
{"id": "andrej-karpathy", "标题": "Andrej Karpathy", "类型": "人物", "文件": "实体/andrej-karpathy.md", "标签": ["AI研究员", "Tesla", "OpenAI"], "更新时间": "2026-04-15"}
{"id": "注意力就是全部", "标题": "《注意力就是全部》（Attention Is All You Need）", "类型": "论文", "文件": "实体/注意力就是全部.md", "标签": ["Transformer", "深度学习"], "更新时间": "2026-04-14"}
{"id": "langchain", "标题": "LangChain", "类型": "工具", "文件": "实体/langchain.md", "标签": ["大语言模型", "框架", "检索增强生成"], "更新时间": "2026-04-16"}
```

## 五、操作日志格式

**路径**：`知识库/操作日志.md`
**更新方式**：每次 ingest 或 consolidate 后追加，**不覆盖历史**

```markdown
---

**处理文件**：
- `原文件名1.md` → 归档为 `已处理/YYYYMMDD_原文件名1.md`
- `原文件名2.txt` → 归档为 `已处理/YYYYMMDD_原文件名2.txt`

**Pending 积压统计**：共 12 条待合并内容
```

## 六、ID 生成规则

`id` 同时是文件名（不含 .md 扩展名），按以下优先级生成：

1. **中文概念**：直接用中文词，如 `注意力机制`、`知识图谱`、`卡片笔记法`
2. **英文专有名词**（模型名、框架名、工具名等）：保留英文小写，词间用连字符，如 `transformer`、`langchain`、`gpt-4`
3. **中英文人名**：中文人名用中文（如 `李飞飞`），英文人名用 `名-姓` 格式（如 `andrej-karpathy`）
4. **论文/书籍**：有中文译名则用中文（如 `注意力就是全部`），无译名则用英文短名
5. **如有歧义**：加类型后缀区分，如 `注意力机制-概念` vs `注意力机制-论文`

**原则**：id 要能直接看出是什么概念，中文读者优先。英文 id 保持全小写。

## 七、Wikilink 交叉引用格式

wiki 页面中引用其他已知概念或实体时，使用 `[[]]` 双向链接语法（与 Obsidian 兼容）。

### 基本语法

| 语法 | 含义 | 示例 |
|------|------|------|
| `[[id]]` | 链接到 id 对应的页面，显示文本为 id 本身 | `[[transformer]]` |
| `[[id\|显示文本]]` | 链接到 id 对应的页面，自定义显示文本 | `[[transformer\|Transformer 架构]]` |

### 规则

1. **id 来源**：使用目标页面的文件名（去掉 `.md` 扩展名），即第六节定义的 id
2. **无需路径前缀**：不写 `[[概念/transformer]]`，直接写 `[[transformer]]`——Obsidian 会自动匹配
3. **插入时机**：
   - **ingest**：写入 `📖 知识摘要`（新页面）或 `📥 待合并内容` 时，自动将文中出现的已知概念/实体名替换为 `[[id]]` 链接
   - **consolidate**：重写 `📖 知识摘要` 时，对已知概念/实体自动补充 `[[id]]` 链接
   - **不回溯**：不主动修改已有页面中的旧文本（lint 可检测缺失的交叉引用）
4. **不重复链接**：同一页面中对同一个 id 只链接首次出现
5. **不自链接**：页面不对自身 id 创建 `[[]]` 链接
6. **兼容性**：`[[]]` 在标准 markdown 渲染器中显示为纯文本（可接受的退化），在 Obsidian/Logseq 中获得完整双向链接体验

## 八、综合分析页模板

**文件路径**：`知识库/综合分析/<id>.md`
**文件名规则**：使用分析主题的简短中文描述作为 id，如 `transformer与bert的关系.md`、`注意力机制演进.md`
**生成来源**：由 `/wiki:query` 的多概念综合回答保存而来，用户确认后创建

```markdown
# <分析标题>

**类型**：综合分析
**来源概念**：`概念1` `概念2` `概念3`
**生成日期**：YYYY-MM-DD
**触发问题**：<用户的原始查询>

---

## 📖 知识摘要

[综合分析内容，引用来源概念的 [[wikilink]]，段落形式]

---

## 参考页面

- [[概念id1]]（最后更新：YYYY-MM-DD）
- [[概念id2]]（最后更新：YYYY-MM-DD）
```

**规则**：
- 综合分析页暂不纳入概念索引或实体索引，仅在 `知识地图.md` 的"最近活跃"中记录
- 综合分析页没有 `📥 待合并内容` 区（它本身就是 query 的产物，不需要二次编译）
- 当未来规模增大时，可为综合分析建立独立索引
