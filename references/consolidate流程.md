# /wiki:consolidate 执行流程

本文件是 `/wiki:consolidate` 命令的完整执行规范。执行时严格按 Step 顺序进行，不可跳步。

---

## 前置说明

- **目标**：将所有 wiki 页面中积压的 `📥 待合并内容` 合并进 `📖 知识摘要`，产出干净、综合的知识页面
- **核心原则**：
  - 合并后 `📖 知识摘要` 区应更完整、更综合，**不丢失任何来源的核心观点**
  - 认知分歧**不消除**，保留在摘要区末尾的独立块中
  - **不自动合并**疑似重复的页面，只记录提示

---

## Step 1：读取配置文件

1. 在当前工作目录查找 `wiki配置.json`
2. 若找不到，输出：
   ```
   ❌ 未找到 wiki配置.json，请先运行 /wiki:init 初始化知识库
   ```
   然后**中止执行**。
3. 解析配置，获取 `知识库路径`。
4. 验证 `<知识库路径>/概念/` 和 `<知识库路径>/实体/` 目录存在。

---

## Step 2：扫描有 Pending 内容的页面

1. 遍历以下两个目录下的所有 `.md` 文件：
   - `<知识库路径>/概念/`
   - `<知识库路径>/实体/`

2. 对每个文件，检测是否有**非空的 `📥 待合并内容` 区**：
   - 定位 `## 📥 待合并内容` 标题行
   - 检查该标题行之后是否有实质内容（不含注释行 `<!-- ... -->`，不含纯空行）
   - 有实质内容 → 加入「待合并页面列表」

3. 统计待合并页面数量。

---

## Step 3：空检查

若「待合并页面列表」为空：

```
ℹ️ 所有页面均已是最新状态，无需合并。
```

**中止执行**。

---

## Step 4：逐页合并

对「待合并页面列表」中的每个页面，执行以下操作：

### Step 4a：读取两个区的内容

1. 读取 `📖 知识摘要` 区的完整内容（从该标题到下一个 `---` 分隔线之间的所有文本）
2. 读取 `📥 待合并内容` 区的所有条目（每个 `> **来源**：...` blockquote 块算一条）
3. 分别提取所有 `⚡ 认知分歧` 块（来自摘要区和待合并区）

### Step 4b：重写 📖 知识摘要

**合并原则**（严格遵守）：

1. **去重**：若多个来源对同一论点有相同或高度相似的描述，合并为一处，保留最清晰的表述
2. **综合**：将各来源的补充信息整合进摘要，形成更完整的知识描述
3. **保留来源引用**：摘要末尾的「来源：...」列表需包含所有贡献过内容的文件名
4. **不丢失**：任何来源中有价值的独特信息都不应在合并后消失
5. **段落形式**：合并后的摘要用流畅的段落写作，而非条目列表

**重写步骤**：
1. 汇总旧摘要 + 所有 pending 条目的内容
2. 识别共同论点，识别补充信息，识别冲突点
3. 撰写新的综合摘要（段落形式）
4. 在摘要末尾汇总所有来源
5. **Wikilink 自动插入**：扫描 `概念索引.jsonl` 和 `实体索引.jsonl`，对新摘要文本中提及的已知概念/实体自动插入 `[[id]]` 链接，规则如下：
   - 每个 id 在同一页面内**仅链接首次出现**
   - **不自链**：当前页面自身的 id 不插入链接
   - 若原文措辞与 id 不同，使用 `[[id|原文]]` 形式（例：文中写"注意力"，id 为 `attention` → `[[attention|注意力]]`）
   - 链接**不加路径前缀**，直接使用裸 id（如 `[[transformer]]` 而非 `[[概念/transformer]]`）

### Step 4c：处理认知分歧块

1. 收集所有 `⚡ 认知分歧` 块（来自旧摘要区 + 待合并区）
2. 对重复的分歧块去重（同一观点、同一来源 → 保留一条）
3. 将所有分歧块放置在新摘要末尾、`来源：` 行之前，形成独立区块：

```markdown
## 📖 知识摘要

[综合摘要段落...]

来源：[文件1]、[文件2]、[文件3]

> ⚡ **认知分歧**
> 外部资料认为：[观点A]
> 来源：[文件名]

> ⚡ **认知分歧**
> 外部资料认为：[观点B]
> 来源：[文件名]
```

### Step 4d：清空 📥 待合并内容区

将 `## 📥 待合并内容` 标题行之后的所有内容清空，仅保留注释提示：

```markdown
## 📥 待合并内容

<!-- ingest 时追加到此区。consolidate 时清空此区内容（保留标题行）。 -->
<!-- 格式：每条独立 blockquote，带来源和日期 -->
```

### Step 4e：更新页面元数据

更新页面顶部的元数据字段：
- `**最后更新**`：改为当前日期（`YYYY-MM-DD`）
- `**有冲突**`：若有 `⚡ 认知分歧` 块 → `是`，否则 → `否`

### Step 4f：更新索引条目

在 `概念索引.jsonl` 或 `实体索引.jsonl` 中找到该页面对应的条目，更新以下字段：
- `更新时间`：改为当前日期
- `有冲突`（仅概念索引）：若存在认知分歧 → `true`，否则 → `false`

**更新方式**：读取整个 `.jsonl` 文件 → 找到对应行 → 替换该行 → 写回文件（保持其他行不变）

---

## Step 5：检测疑似重复页面

扫描完所有页面后，进行相似度检测：

### 检测规则

对知识库中**所有**概念页（不仅限于本次合并的页面），两两比较标题相似度：

1. **完全包含**：标题 A 是标题 B 的子串（如 `注意力` vs `注意力机制`）→ 疑似重复
2. **高度相似**：两个标题的核心词汇高度重叠（由 LLM 语义判断，阈值：>80% 相似）→ 疑似重复
3. **中英文同义**：一个是中文，另一个是对应英文（如 `变换器` vs `Transformer`）→ 疑似重复

### 处理方式

- **不自动合并**，不修改任何文件
- 在操作日志中记录提示：
  ```
  ⚠️ 疑似重复页面（请人工确认）：
  - `概念/attention.md`（注意力）与 `概念/zhu-yi-li-ji-zhi.md`（注意力机制）标题相似
  ```
- 向用户展示这些提示，供人工判断

---

## Step 6：更新知识地图

更新 `<知识库路径>/索引/知识地图.md`，反映最新状态：

1. **统计数据更新**：
   - 读取 `概念索引.jsonl` 统计概念总数
   - 读取 `实体索引.jsonl` 统计实体总数
   - 统计仍有 pending 内容的页面数（本次合并后应为 0，但可能有新增的）
   - 统计 `有冲突: true` 的概念页数量

2. **⚡ 有认知分歧的条目**表格：更新为所有 `有冲突: true` 的页面列表

3. **📥 待合并积压**表格：更新为当前所有仍有 pending 内容的页面（本次 consolidate 后通常为空）

4. **最近活跃**列表：在列表顶部插入本次合并的页面记录（最多保留 10 条）

5. 更新文件顶部的 `**最后更新**` 字段

**注意**：领域分布区块**不自动重写**（避免破坏用户手动整理的结构），只更新统计数字和动态表格。

---

## Step 7：写操作日志

在 `<知识库路径>/操作日志.md` 末尾追加：

```markdown
---

### [YYYY-MM-DD HH:MM] /wiki:consolidate | 合并 N 个页面，检测到 M 处认知分歧

**合并页面**：
- `概念/xxx.md`（概念标题）：合并 N 条 pending，📖 知识摘要已更新
- `概念/yyy.md`（概念标题）：合并 N 条 pending，检测到 ⚡ 认知分歧（N 处），已标注
- `实体/zzz.md`（实体标题）：合并 N 条 pending，📖 知识摘要已更新

**疑似重复页面提示**：
- （无 / 具体描述）

**知识地图**：已更新
**合并后 Pending 积压**：共 N 条（理想为 0）
```

向用户展示操作摘要：

```
✅ /wiki:consolidate 完成

合并页面：N 个
消化 pending 条目：N 条
检测到认知分歧：N 处
疑似重复提示：N 组（请人工确认）

[如有疑似重复]
⚠️ 以下页面可能重复，请人工确认是否合并：
- `xxx.md` 与 `yyy.md`
```

---

## 合并质量要求

LLM 在重写 `📖 知识摘要` 时，最终结果应满足：

| 要求 | 说明 |
|------|------|
| 完整性 | 合并后的摘要包含所有来源的核心信息 |
| 简洁性 | 去除重复表述，不堆砌 |
| 可读性 | 流畅的段落，而非条目堆叠 |
| 溯源性 | 来源引用完整，可追溯到具体文件 |
| 分歧显式 | 所有认知矛盾用 ⚡ 标注，不静默消除 |

---

## 错误处理

| 情况 | 处理方式 |
|------|----------|
| `wiki配置.json` 不存在 | 中止，提示运行 /wiki:init |
| 概念/实体目录不存在 | 提示目录缺失，中止 |
| 单个页面读取失败 | 跳过该页面，记录错误到日志，继续处理其他页面 |
| 索引更新失败 | 记录错误到日志，标记需要手动修复 |
| 知识地图更新失败 | 记录错误到日志，不影响页面合并结果 |
