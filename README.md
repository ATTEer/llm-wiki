# llm-wiki skill：编译型个人知识库

> 🧠 不是 RAG，是预编译 wiki。原始资料 → 编译 → 知识页面 → 查询。

---

## 核心理念

基于大神思路制作的SKILL，原文： https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f.js" 
llm-wiki 是一个**编译型知识库系统**，与传统 RAG（检索增强生成）有本质区别：

| 对比维度 | 传统 RAG | llm-wiki |
|----------|----------|----------|
| 知识形态 | 原始文档片段 | 预合成 wiki 页面 |
| 查询时工作 | 每次从原文推导 | 读已合成的 wiki |
| 知识积累 | 原文堆叠 | 持续编译、去重、综合 |
| 认知冲突 | 隐藏在原文中 | 显式 ⚡ 标注 |

**核心流程**：
```
原始资料 → /wiki:ingest（追加 pending）→ /wiki:consolidate（编译成 wiki）→ /wiki:query（读 wiki 回答）
```

## 快速开始

### 1. 初始化知识库

```
/wiki:init
```

或中文触发词：
```
初始化知识库
```

这会在当前目录创建知识库结构：
```
./
├── wiki配置.json
├── 原始资料/
│   ├── 待处理/        ← 把你收集的文章放这里
│   ├── 已处理/        ← 系统自动归档
│   └── 卡片/          ← 预留接口
└── 知识库/
    ├── 索引/
    │   ├── 概念索引.jsonl
    │   ├── 实体索引.jsonl
    │   └── 知识地图.md
    ├── 概念/
    ├── 实体/
    ├── 综合分析/
    └── 操作日志.md
```

### 2. 放入资料

将你的文章（.md 或 .txt）放入 `原始资料/待处理/` 目录。

### 3. 摄入知识

```
/wiki:ingest
```

系统会自动：
- 提取概念和实体
- 匹配已有 wiki 页面
- 追加到待合并区（pending）
- 归档原始文件

### 4. 合并知识

当 pending 内容积累到一定程度：

```
/wiki:consolidate
```

系统会将 pending 内容合并到知识摘要区，重写摘要、处理认知分歧。

### 5. 查询知识库

```
/wiki:query 什么是注意力机制？
告诉我关于 transformer 的内容
知识库里有什么关于 RAG 的？
```

## 子命令详解

### `/wiki:init` — 初始化知识库

**触发词**：`/wiki:init`、`初始化知识库`、`wiki init`

创建知识库目录结构和配置文件。如果 `wiki配置.json` 已存在，会询问是否重新初始化。

---

### `/wiki:ingest` — 摄入新资料

**触发词**：`/wiki:ingest`、`处理文章`、`ingest`、`摄入资料`、`处理笔记`

扫描 `原始资料/待处理/` 目录，处理其中的文章：

1. **提取概念+实体**：从文章中识别关键概念和实体
2. **索引匹配**：与现有 wiki 页面进行模糊匹配
3. **追加 pending**：将新知识追加到对应页面的 `📥 待合并内容` 区
4. **归档原文件**：处理完成后移动到 `已处理/` 目录

**输出示例**：
```
✅ 处理完成：attention_is_all_you_need.md
   - 提取概念：注意力机制、Transformer、自注意力
   - 匹配页面：注意力机制.md（追加 pending）
   - 新建页面：Transformer.md
   - 已归档到：原始资料/已处理/20260416_attention_is_all_you_need.md
```

---

### `/wiki:consolidate` — 合并知识

**触发词**：`/wiki:consolidate`、`合并知识`、`consolidate`、`整理知识库`

将所有页面的 `📥 待合并内容` 合并到 `📖 知识摘要` 区：

1. 重写知识摘要（综合多方信息）
2. 处理认知分歧（显式标注冲突观点）
3. 检测重复页面并提示合并
4. 更新知识地图

**认知分歧处理**：
当不同来源对同一概念有不同观点时，使用 `⚡ 认知分歧` 标注块显式记录，而不是静默取舍。

```markdown
⚡ 认知分歧
外部资料《XXX》认为：「注意力机制的计算复杂度是 O(n²)」
与当前摘要的冲突点：复杂度应该是 O(n) 在某些优化场景下
建议：需要进一步验证
```

---

### `/wiki:query` — 查询知识库

**触发词**：`/wiki:query`、`查询知识库`、`告诉我关于...`、`wiki query`、`知识库里有什么关于...`

基于 wiki 页面内容回答用户问题：

- 扫描概念索引和实体索引
- 读取匹配的 wiki 页面
- 基于 `📖 知识摘要` 区回答
- 标注来自 `📥 待合并内容` 的信息
- **主动浮出认知分歧**

**输出示例**：
```markdown
注意力机制（Attention Mechanism）是一种...

---
**参考了 2 个 wiki 页面**：
- 注意力机制.md（最后更新：2026-04-16）
- Transformer.md（最后更新：2026-04-15）

**⚡ 注意：以下内容存在认知分歧**
- 注意力机制：外部资料认为「计算复杂度是 O(n²)」，来源：paper_v2.md
```

**自动保存综合分析**：
当回答涉及 2 个或以上概念时，会询问是否保存到 `综合分析/` 目录。

---

### `/wiki:lint` — 健康检查

**触发词**：`/wiki:lint`、`健康检查`、`lint`、`检查知识库`

执行 5 项检查：

| 检查项 | 说明 |
|--------|------|
| 孤儿页 | 没有被索引引用的 wiki 页面 |
| pending 堆积 | `📥 待合并内容` 过长的页面 |
| 缺失页面 | 索引中有但文件不存在的条目 |
| 过时页面 | 长期未更新的页面 |
| 交叉引用完整性 | 页面中的 wikilink 是否有效 |

## 页面格式

### 概念页模板

```markdown
# 概念名

标签：#标签1 #标签2

---

## 📖 知识摘要

（已合并的权威知识）

## 📥 待合并内容

（新摄入、待整合的内容）

## ⚡ 认知分歧

- 观点 A vs 观点 B

## 🔗 相关概念

- [[其他概念]]

## 📚 来源

- 文章名（文件名）
```

### 索引格式

**概念索引.jsonl**（每行一条 JSON）：
```json
{"标题": "注意力机制", "标签": ["深度学习", "NLP"], "文件": "概念/注意力机制.md", "更新": "2026-04-16"}
```

**实体索引.jsonl**：
```json
{"标题": "Vaswani", "类型": "人", "标签": ["研究者"], "文件": "实体/Vaswani.md"}
```

## 配置说明

**wiki配置.json**：
```json
{
  "知识库路径": "./知识库",
  "原始资料路径": "./原始资料",
  "卡片路径": null,
  "卡片格式": null
}
```

- 支持相对路径（相对于配置文件所在目录）和绝对路径
- `卡片路径` 为 `null` 时跳过卡片处理

---

## 设计原则

1. **原始资料目录只读**：只移动，不修改原始文件
2. **中文优先**：目录、标题、标签使用中文（英文专有名词保留）
3. **认知分歧显式化**：不静默合并冲突观点
4. **知识摘要区 ingest 时只读**：只能追加到待合并区
5. **日志只追加不覆盖**：完整操作历史

## 跨 skill 协作

当 `待处理/` 目录中有不支持的文件格式时：

| 文件类型 | 推荐处理方式 |
|----------|--------------|
| .pdf | 使用 pdf skill 提取文本 |
| 图片 | 使用支持视觉的 LLM 描述后保存为 .md |
| .html | 使用 wechat-download skill 转换 |
